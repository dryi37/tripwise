# Tripwise UX contract
Purpose: consultants combine client requirements, internal knowledge and external sources into an editable itinerary and quotation. No live AI/search/booking in this prototype.

Local list search uses existing hash URL state. Source query is transient sample-catalog state. All results explicitly say demonstration. Source addition requires explicit confirmation and records a source snapshot in selected trip quotation. Existing matched internal rates update instead of duplicating. Trips and locked activities remain intact. Source filters never query online. Prices do not imply availability. Preview/export never send proposals or book services. Snapshots atomically pair requirements, activities and quotes with provenance.
Supplier pricing is a two-level local catalog: service group then supplier offer. Navigation calls it “Danh mục nhà cung cấp”; trip discovery and calculation share the “Báo giá” tab. Its inline “Thêm dịch vụ” picker is read-only against catalog data, marks already-added sources, and returns to the quote table after an explicit add. Selecting an offer in the catalog stays in the catalog and never mutates a trip. “Apply to trip” is atomic: if any selected offer is missing, unverified or expired before departure, no quote row is changed. A successful apply preserves quantities, references exactly one service/offer pair, and copies provider, validity, terms and verification into each quote row. The quote source link returns to that exact catalog offer.
Manual quote services are created from the unified quote surface and remain `UNVERIFIED`. Required values are service name, provider and unit; quantity is an integer from 1 and VND price is a non-negative integer. “Lưu vào Danh mục nhà cung cấp” is off by default. When selected, the quote row and its single unverified supplier offer are persisted atomically and linked by exact IDs; failure restores both collections.
In the service catalog, the service name opens one editor for service metadata and its single supplier offer. The table has no action column; the editor owns the delete action. Deleting a service means deactivating it, preserving price and historical quote links, and requires an app-owned confirmation that names this consequence.
The service page separates “Nội bộ” catalog entries from “Bên ngoài” activities that have a saved web URL. Each external activity appears as its own row across trips; its source link sits beside the service name, and its quote, trip, and source details stay on that row without adding a link column.

New activities require a concrete OpenStreetMap place candidate. The picker is debounced, supports keyboard and pointer selection, and shows the address to distinguish branches. Editing other fields on an older activity remains possible; changing its venue requires selecting a new candidate. Agent-created activities require a valid candidate from the same agent run and a non-empty `selectionReason`.

The itinerary map uses Leaflet with OpenStreetMap tiles, follows the selected day, and shows one numbered marker per distinct place group. Marker hover, focus, and tap show the linked activity and its `selectionReason`; the activity timeline remains the accessible fallback. Map hydration is transient and never enters trip snapshots or browser cache. Activities without a resolvable Place ID are listed as unresolved and receive no fabricated marker.
Use shared buttons, modal, forms, toast and money formatting. Native field semantics retained, validation is app-owned. Errors preserve input and focus correction. Nonempty search has clear action. Search clearing returns focus. Destructive confirmations focus Cancel. Remote integrations are not active. Tables own horizontal overflow; document owns vertical flow. Finite local lists show result counts. No frontend secrets or real personal data.
